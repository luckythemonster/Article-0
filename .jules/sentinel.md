## 2025-07-29 - [Clean Object Reconstruction to Block Prototype/Property Pollution]
**Vulnerability:** Loading un-sanitized parsed JSON files from localStorage using the object spread operator (`...v`) or recursive merge allows attackers or hand-edited saves to pollute the prototype or inject unexpected keys directly into runtime data structures, which can trigger undefined behaviour, property pollution, or path/directory traversal via manipulative `level` strings.
**Learning:** Reconstructing the loaded data structure field-by-field with validated primitive types and strictly constructed sub-objects is a powerful, highly resilient defense-in-depth pattern. It avoids any exposure to unexpected fields and prototype/property pollution vectors entirely.
**Prevention:** Strictly limit string lengths, validate level name format using precise regular expressions (e.g., `/^[a-zA-Z0-9_-]+$/`), and explicitly construct newly validated return structures instead of spreading parsed JSON directly.

## 2025-08-11 - [Safeguarding localStorage Sub-State Validation and Object Prototype Injection]
**Vulnerability:** While parent save games were sanitized, sub-state validators like `isJournalState` and `isExploredState` lacked bounds and pattern checking, leaving the application vulnerable to Denial of Service (DoS) from bloated states or character injection. Additionally, helper parsed configurations (like settings) were queried directly, allowing inherited properties on `Object.prototype` to override application-level defaults.
**Learning:** Checking prototype keys (`__proto__`, `constructor`) inside validators and using `Object.prototype.hasOwnProperty.call` ensures properties are queried only from the object's own direct fields. A key challenge was that JS object literals `{ "__proto__": "value" }` modify the object's internal prototype instead of creating an own property, which prevents serialization. This requires the use of `Object.defineProperty` with `enumerable: true` during testing to correctly emulate a JSON-parsed payload with an own `"__proto__"` key.
**Prevention:** Enforce strict size/length bounds, sanitize keys against exact alphanumeric patterns, reject prototype properties explicitly, and retrieve properties using `hasOwnProperty` to completely bypass prototype pollution access vectors.
